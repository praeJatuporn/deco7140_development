Overview of Implementation

Colour scheme changed

I adjusted the overall theme to use a warmer and more visually comfortable colour palette. The new colours are generally softer and easier on the eyes compared to the original design. Bright and fresh tones were chosen to better reflect the creative and handmade nature of the site, while still maintaining the warmth associated with yarn and handcrafts. Darker shades, such as black and green, are reserved for key interactive elements like buttons, helping to draw user attention without overwhelming the interface. Overall, this new palette improves readability, adds personality, and enhances the site's alignment with its craft-inspired identity.

Form and Button changed

Form fields were reorganised to improve usability, and interactive features such as album search and event booking were implemented using JavaScript to enhance user engagement. Button components were redesigned to provide clearer affordance and ensure better accessibility compliance. In addition, colours and fonts were selected based on WCAG guidelines, following an accessibility assessment conducted using Chrome’s accessibility tools.

Menu changed

To support the large number of main and sub-pages, the navigation was redesigned from a traditional icon bar to a hamburger menu. This provides a cleaner and more organized layout, especially for mobile and small screen users, helping community members who access the site across various devices. The update also meets the client’s request for a scalable and user-friendly interface that can grow with features like events, group page, and tutorials. The hamburger menu improves usability by reducing visual clutter while maintaining full access to all sections. It also complies with WCAG guidelines through keyboard navigation, screen reader compatibility with ARIA labels, and clear contrast and focus indicators for interactive elements.

Links styles changed

Previously, most links on the website were plain text styled only in blue, without underline or hover effects. This made it difficult for users to identify which elements were interactive. To address this, all links were enhanced with hover effects and clearer visual indicators, such as underlining or color transitions. These changes improve affordance and ensure better compliance with WCAG guidelines for perceivable and operable user interface components.

Gallery page changed

The Gallery page was redesigned for better usability and clarity. The search function now uses a more intuitive icon with an input placeholder guiding users to search for images or albums. JavaScript enables real-time searching across both albums and member uploads. A new showcase section was added below the main albums, displaying member-shared images in a responsive grid. Each image opens in a custom viewer for clearer detail due to their small default size. Clickable links below image captions direct users to the member’s inspiration page, improving navigation, promoting engagement, and aligning with the client’s goal to highlight community contributions.

Rationale for Implementation Decisions

Homepage

🎯Key Components: A hero image with the site name creates a strong first impression, followed by a short purpose text. Main activities are shown using grid cards and yellow-hover text links, leading to project pages for admins and members. Green call-to-action buttons encourage exploration. The footer includes links like About, Contact, and branding.

🎯Design Rationale: The design helps users understand the community's focus with a warm, creative tone matching the crafting theme. It promotes participation and meets client needs by fostering interaction. Clear communication ensures accessibility for all user levels.

contact us

🎯 Key Components: A hero image sets a welcoming tone, followed by a clear title and intro text. The contact form includes labeled fields for name, email, message, and optional photo upload. A styled "Send" button submits the form, and feedback appears below with success/error messaging.

🎯 Design Rationale: Designed for user-friendly communication, the form encourages member interaction while maintaining simplicity. It supports client needs by enabling outreach and feedback. Accessibility is prioritized through proper labels, live feedback, and keyboard-friendly navigation, aligning with WCAG standards.

Personal detail

🎯Key Components: A structured form with fields for name, email, location, hobbies and some details about the user and photo upload. A Submit button uses JavaScript to provide real-time success or error feedback.

🎯Design Rationale: The form uses clear labels, semantic structure, and accessible inputs to support screen readers, and meet WCAGhelping users confidently share personal details and build community connections.

🎯Why: JavaScript simulates data editing and submission without backend/API integration. This suits project constraints and allows intuitive interaction while demonstrating functionality without live processing.

Group profile

🎯 Key Components: The Group Profile page shows a group avatar, title, and description for the “Craft Lovers Group.” Below are visual cards of group posts with images, captions, and simulated “Like” and “Comment” buttons.

🎯 Design Rationale: Supports the client’s goal to build community. The avatar adds identity, and the post section encourages sharing. The layout is accessible, intuitive, and WCAG-compliant.

🎯 Why: Buttons are simulated due to project limits. This shows intended interaction without needing backend integration.

Calendar

🎯Key Components: A grid calendar displays daily events clearly. Using javaScript search bar filters events in real-time. A simulated “Subscribe to Calendar” button hints at future features. Each event can be click and link to the event page.

🎯 Design Rationale: The "Subscribe" button reflects the client's Value 5 flexibility, allowing users to manage schedules visually.

🎯 Why: Using only HTML/CSS, the button offers a realistic simulation without backend code, aligning with the project’s scope.

Events

🎯 Key Components: The page shows a grid of cards with an image, short description, and two buttons. “Book this Event” links to the booking form, while “Add to Calendar” simulates future calendar integration.

🎯 Design Rationale: Supports the client’s goal of boosting participation through clear event info and CTAs. The booking button enables direct action, and the calendar button hints at flexible scheduling (Client Value 5).

🎯 Why: Calendar integration is out of scope, so the button is styled only with HTML/CSS. Booking uses simple navigation, balancing real function and future potential in a user-centered, accessible way.

Book

🎯 Key Components: A clear event registration form with a radio group inside an accordion. A live feedback area shows success or error messages after submission.

🎯 Design Rationale: Built for clarity and accessibility using semantic elements and ARIA. The accordion reduces clutter and helps users select one event, meeting the client’s need for intuitive registration.

🎯 Why: JavaScript simulates form submission and feedback without backend use. This matches project scope and offers a realistic, engaging experience.

Paper Instruction

🎯Key Components:The Paper Instruction page features article cards in a responsive grid. Each card has an image, title, description, and a styled “Learn more” button that simulates real UI functionality.

🎯Design Rationale: The card layout supports quick scanning and visual learning. Hover effects add interactivity, and the green “Learn more” button with color change on hover aligns with other CTAs.

Album

🎯 Key Components: The page includes a section title, search bar with icon, and three grid cards for main craft categories (simulated clickable). A user showcase displays member-uploaded images with click-to-enlarge and captions linking to full galleries (Pear only).

🎯 Design Rationale: Supports exploration and connection through shared content. The search bar aids discoverability, while hover effects and image viewer improve usability and interaction.

🎯 Why: JavaScript simulates real-time filtering and image viewing. Though links aren't live, they hint at future content browsing features.

WCAG Accessibility Implementation and IBM checker on Chrome

Semantic HTML structure

The website’s HTML structure is designed using semantic tags such as nav, main, section, and article, allowing screen readers to better interpret the content. This clear categorization improves the overall user experience, especially for individuals with visual impairments.

Violation scanned

"Accessible name does not match or contain the visible label text"

To solve this, I changed the button label from 'Member Log in' to 'Member Logging' to match the aria-label on index.html."
